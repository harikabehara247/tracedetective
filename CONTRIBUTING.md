# Contributing to TraceDetective

Thanks for helping. Bug reports, docs fixes, new test cases and new diagnostic rules are all welcome.

## Setup

```bash
npm install
npm run dev
```

Before opening a pull request, run:

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e   # for UI changes
```

## Ground rules

- Keep `src/core` free of DOM and React code so it stays easy to test.
- Never commit secrets, credentials or real trace data. Test fixtures must be synthetic and marked `"synthetic": true`.
- Render imported values as text. Do not use `dangerouslySetInnerHTML` or evaluate imported data.
- Keep claims honest. Do not add numbers, benchmarks or comparisons that are not reproducible from the repository.

## Adding a diagnostic rule

1. Add a function in `src/core/diagnostics.ts` that returns `Finding[]`, and register it in `runDiagnostics`.
2. Every finding needs an observation, evidence that names spans and numbers, possible explanations, things to verify next, and a caveat that says what the rule cannot prove.
3. Put any threshold in `RULE_THRESHOLDS` and document it on the Docs page.
4. Add tests in `tests/core.test.ts` for a trace that triggers the rule and one that does not.

## Fixtures

The sample traces are generated by `scripts/generate-fixtures.py` (`npm run fixtures`). Change the script, not the JSON files.

## Commit messages

Use short imperative subjects, for example `Add retry detection rule`. Explain the reason in the body when it is not obvious.
